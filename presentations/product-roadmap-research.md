# ข้อเสนอผลิตภัณฑ์ถัดไปของ AlexiaSoft

ศึกษาหน้าเว็บจริงวันที่ 2 ตุลาคม 2026 · เป็นข้อเสนอเชิงกลยุทธ์ ไม่ใช่ผลวิจัยลูกค้าไทยหรือแผนที่รับประกันรายได้

## ข้อสรุป

แนะนำ **MintCollect** (ติดตามใบแจ้งหนี้และนัดชำระ) ก่อน **MintApprove** (อนุมัติคำขอซื้อ/ค่าใช้จ่าย) ทั้งสองเป็นชื่อทำงาน ต้องตรวจโดเมนและเครื่องหมายการค้า ทั้งสองยังไม่ใช่สินค้าที่พัฒนาแล้ว

ให้ **MintERP เป็นสินค้าหลักของบริษัทและฐานแผน reseller 5 ปี** ส่วน MintPOS เป็นระบบขายหน้าร้านที่มีบทบาทแยกกัน ไม่ถือว่าเชื่อมข้อมูลกันแล้ว ผลิตภัณฑ์ใหม่ต้องขายแยกได้โดยไม่บังคับเปลี่ยน ERP และไม่ทำซ้ำฟีเจอร์ที่ลูกค้ามีครบอยู่แล้ว

ไม่มีผลิตภัณฑ์ใดที่ทุกองค์กรต้องซื้อ เราจึงเลือกปัญหาข้ามอุตสาหกรรม แต่เริ่มจากกลุ่มแคบที่มีปัญหาซ้ำและมีผู้รับผิดชอบงบชัดเจน

## 2. ความเหมาะสมกับผู้ก่อตั้ง

หลักฐานที่มีคือเว็บไซต์ Laravel 8 และคำอธิบายบริการ ERP/POS, บัญชี, workflow, web/mobile และ API integration ใน repository ไม่ใช่ประวัติทักษะส่วนบุคคลหรือ code audit ของ MintERP/POS

ทั้งสองแนวคิดใช้ทักษะใกล้กับฐานนี้: data model, CRUD, authorization, queue/scheduler, email, CSV, audit trail และการเก็บ requirement ธุรกิจ ไม่ต้องสร้าง ML model, hardware, core banking หรือ tax engine

ก่อนเริ่มต้องตรวจสิทธิ์ reuse code และความพร้อมทีม ใช้ framework รุ่นที่ยังได้รับ security support สำหรับผลิตภัณฑ์ใหม่ ไม่คัดลอก Laravel 8 จากเว็บนี้ไปเป็นระบบ SaaS ใหม่โดยไม่ประเมิน

## 3. MintCollect — แนะนำให้ทดสอบก่อน

- **กลุ่มแรก:** ค้าส่ง/บริการ B2B ที่ขายเชื่อ มี 100–1,500 ใบแจ้งหนี้ต่อเดือน และยังตามเงินด้วย Excel/email
- **ผู้จ่าย:** เจ้าของกิจการหรือหัวหน้าการเงิน; ผู้ใช้คือทีมบัญชี/credit control
- **งานที่จ้างระบบมาทำ:** จัดคิวตามบิล รู้ผู้รับผิดชอบ เหตุผลค้าง นัดชำระ และประวัติ ไม่ให้ต้องเปิดหลายไฟล์ถามซ้ำ
- **ไม่ใช่ลูกค้าแรก:** ธุรกิจรับเงินสดครบทุกบิล บริษัทที่ AR เดิมตอบโจทย์ครบ หรือองค์กรที่ต้องการ bank integration ทันที
- **จุดขายเสนอ:** ข้อมูลเข้าแบบ CSV โดยไม่ย้าย ERP, template ภาษาไทย, นัดชำระ/ข้อพิพาทเป็นสถานะชัดเจน และ partner ช่วยเริ่มใช้ได้ภายใน 1 วันเมื่อข้อมูลพร้อม
- **เหตุผลเลือกก่อน:** อยู่ใกล้ความเชี่ยวชาญบัญชี/ERP และมีตัวชี้วัดเวลางานที่ชัด แต่การได้เงินเร็วขึ้นขึ้นกับลูกหนี้และข้อพิพาทด้วย ไม่รับประกัน DSO

### MVP 12 สัปดาห์

1. Tenant และ 5 staff accounts: admin/finance/operator, THB, 1 บริษัทต่อ tenant
2. CSV ลูกหนี้/บิล/ยอดชำระ พร้อม mapping คงที่, preview/error report, stable invoice ID และ duplicate validation
3. รองรับยอดชำระบางส่วน aging bucket, ผู้รับผิดชอบ, วันนัดชำระ และ dispute/pause
4. Email template ไทย 3 ระยะ พร้อมคิวตรวจโดยเจ้าหน้าที่ก่อนส่ง ไม่ส่งอัตโนมัติโดยไม่อนุมัติ
5. ต้องยืนยันข้อมูลชำระไม่เกิน 24 ชั่วโมงก่อนส่ง มิฉะนั้น hold; ส่งจริงตรวจสถานะอีกครั้ง กันส่งซ้ำและมี retry/bounce log
6. ประวัติการติดตามและ CSV export; ยอดบัญชีหลักยังอยู่ที่ระบบเดิม
7. Tenant isolation, permission tests, private data, retention, backup และ restore drill

ขอบเขต pilot เสนอ: 2,000 open invoices และ 5,000 emails/เดือน/tenant ไม่รวมไฟล์ประวัติไม่จำกัด

**ตัดออก:** bank feeds, รับ/โอนเงินจริง, e-Tax, OCR, credit scoring, การทวงหนี้แทนลูกค้า, native app, LINE/WhatsApp และระบบ AI ส่งข้อความเอง API ของ MintERP เป็น optional หลังยืนยัน endpoint; CSV ต้องทำงานได้โดยไม่รอ connector

**เกณฑ์ทดลอง:** 3 บริษัท, ≥2 ตกลง paid pilot, ลดเวลางานติดตาม ≥30% เทียบ baseline เดิมใน 4 สัปดาห์ เก็บ DSO/overdue ratio เป็นตัวติดตามระยะยาว ไม่ใช้ผล 3 บริษัทเป็นข้อสรุปเชิงสถิติว่าตลาดทั้งหมดได้ผล

## 4. MintApprove — ตัวเลือกที่สอง

- **กลุ่มแรก:** องค์กร 10–30 ผู้ใช้ หลายแผนก/สาขา อนุมัติผ่านแชตและอีเมล ยังไม่มี workflow ที่พอใช้
- **ผู้จ่าย:** เจ้าของ/ธุรการ/การเงิน; ผู้ใช้คือพนักงานและผู้อนุมัติ
- **งานที่จ้างระบบมาทำ:** คำขอมีหลักฐานครบ รู้ว่าติดที่ใคร ใช้ policy เดียวกัน และตรวจประวัติได้
- **จุดขายเสนอ:** 2 template ไทยพร้อมใช้ มี partner ตั้ง policy ไม่ต้องออกแบบ low-code ตั้งแต่ศูนย์ และไม่บังคับเปลี่ยน ERP
- **ข้อได้เปรียบต้องพิสูจน์:** ไม่ใช่ภาษาไทยอย่างเดียว แต่เวลา setup ค่าแรงสนับสนุน และการใช้งานจริง ต้องดีกว่าทางเลือกที่ลูกค้ามีอยู่

### MVP 12 สัปดาห์

1. หนึ่งบริษัท/tenant, 30 users, 500 requests/เดือน
2. Form คำขอซื้อและขออนุมัติค่าใช้จ่าย พร้อมไฟล์แนบและผู้รับผิดชอบ
3. สายอนุมัติคงที่เลือกตามแผนก/วงเงิน สูงสุด 3 ขั้น แบบ sequential เท่านั้น
4. อนุมัติ/ไม่อนุมัติ/ส่งกลับแก้ไข และ email reminder
5. ห้าม self-approve, server-side authorization ทุก action, ป้องกัน double action
6. เก็บ revision ของคำขอและ policy; เปลี่ยนยอดหลังยื่นต้องเริ่มอนุมัติใหม่
7. ระยะเวลาค้าง, PDF/CSV export และ audit history; attachment private พร้อมตรวจชนิด/ขนาด/มัลแวร์

**ตัดออก:** workflow builder/BPMN, parallel flows, delegation ซับซ้อน, payroll/leave, budget reservation, เงินโอน, e-signature รับรองทางกฎหมาย, SSO enterprise, on-prem, native app, OCR และ AI อนุมัติ

หาก approver ไม่อยู่ ใช้ยกเลิกและยื่นใหม่พร้อม log ใน MVP หากธุรกิจรับข้อจำกัดนี้ไม่ได้ ไม่ใช่กลุ่ม pilot แรก

**เกณฑ์ทดลอง:** ≥2/3 pilot ยอมจ่าย ลด median approval lead time ≥30% โดยเก็บทั้งปริมาณและความซับซ้อนคำขอ และไม่มี critical authorization defect

## 6. ราคาและเศรษฐศาสตร์ที่เสนอ (ไม่ใช่ราคาเปิดขายจริง)

หน่วยบาท ไม่รวม VAT; รายปีเป็นราคาแพ็กเกจส่วนลด ไม่ใช่รายเดือน ×12

| รายการ | MintCollect | MintApprove |
|---|---:|---:|
| รายเดือน | 1,490 | 990 |
| รายปี | 14,900 | 9,900 |
| Setup ครั้งแรก | 4,900 | 3,900 |
| Partner subscription 30% | 4,470 | 2,970 |
| Partner setup 70% | 3,430 | 2,730 |
| Partner รวมปีแรก | 7,900 | 5,700 |
| บริษัทหลังแบ่ง ปีแรก (ก่อนต้นทุน) | 11,900 | 8,100 |
| ต้นทุนบริการผันแปรสมมติต่อเดือน | 300 | 200 |
| Contribution ต่อ renewal เต็มปี | 6,830 | 4,530 |

ต้นทุนบริการเสนอรวม cloud/email/การสนับสนุนผันแปร ต้องวัดจริง ยังไม่รวมพัฒนา CAC overhead ภาษีและค่าเริ่มใช้งาน

สมมติ partner ใช้เวลา setup 4 ชั่วโมง ×300 =1,200 บาท: เหลือส่วนติดตั้ง Collect 2,230 / Approve 1,530 บาท ก่อนค่าเดินทาง ขาย และ overhead ของ partner ไม่ใช่กำไรสุทธิ และไม่ควรรับ custom ไม่จำกัดในราคานี้

ตัวอย่าง 20 บัญชีต่อสินค้า: gross ARR 496,000 บาท; partner 148,800; บริษัทหลังแบ่ง 347,200 ก่อนต้นทุน หากเกิดพร้อมกันครบ 12 เดือน ต้นทุนบริการสมมติ 120,000 รวมสองสินค้า เหลือ contribution 227,200 บาท ไม่รวม setup และยังไม่พอคืนทุนพัฒนาสองสินค้าในปีเดียว

การคืนเฉพาะต้นทุนพัฒนา 561,000 ด้วย renewal contribution ต้องประมาณ 83 customer-years สำหรับ Collect หรือ 124 สำหรับ Approve (ปัดขึ้น) โดยยังไม่หัก CAC/overhead ไม่ใช่ payback period เพราะยังไม่รู้ความเร็วการขายและ churn

**ไม่เพิ่มตัวเลขเหล่านี้ใน MintERP base case 5 ปี:** เป็น optional upside ไม่ใช่สัญญาว่าขายได้ และไม่ควรนับซ้ำกรณีขาย bundle

| สัปดาห์ 10–12 | Pilot 3 บริษัท เก็บ baseline/ผลลัพธ์ แก้ข้อผิดพลาด ส่งคู่มือและตัดสิน go/no-go |

MVP done หมายถึง pilot ใช้งานจริงตามขอบเขต ไม่ใช่ demo คลิกได้ แต่ยังไม่ใช่ enterprise-ready ทุกอุตสาหกรรม

งบเสนอ: dev 2 ×60,000 ×3 =360,000; QA 0.5 ×40,000 ×3 =60,000; founder 0.25 ×80,000 ×3 =60,000; tools/security 30,000; reserve 10% ของ 510,000 =51,000 รวม **561,000 บาทต่อ MVP** ค่าแรงเป็นสมมติฐานและมี opportunity cost แม้ founder ไม่รับเงินเดือน

ทีมเดียวทำ MintCollect ก่อน หากผ่าน gate จึงทำ MintApprove รวมสองรอบ 24 สัปดาห์ ไม่อ้างว่าทำสองตัวพร้อมกันจบใน 3 เดือน ถ้าต้องทำพร้อมกันต้องแยกกำลังทีมและทบทวนงบ หากทำคนเดียวต้องลด scope และประเมินใหม่ ไม่รับประกันเวลาเดิม

สองสินค้ารวม 1.122 ล้านบาท ซึ่งเกือบเท่างบ product เดิม 1.2 ล้านบาทใน deck แต่เงินเดิมยังต้องใช้ดูแล MintERP จึงต้องอนุมัติงบเพิ่มหรือปรับ allocation อย่างเปิดเผย ไม่ถือว่าทำฟรีได้จากงบเดิม และไม่ลด security/validation เพื่อให้ทันเส้นตาย
